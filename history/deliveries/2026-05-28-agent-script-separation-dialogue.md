## 核心（1行）

**推論（エージェント）と決定論（スクリプト）を組み合わせる。鍵は「どこに何を置くか」で、判断軸は2つ —— ①取り返しがつくか ②仕様がはっきりしているか。**

---

## 1. 記事の事故の本当の正体

- 表面：context（言葉）が code（操作）を上書きした。`from issue to merged PR` の一文が、コードに無い merge を起こした。
- 本質は「agent か script かの選び間違い」ではなく、**「確定していない意図に、取り返しのつかない権限を渡した」**こと。

## 2. 担当を決める2軸マトリクス

| | 可逆（取り返しがつく） | 不可逆（取り返しがつかない） |
|---|---|---|
| **仕様が確定** | スクリプト（← 皆がサボってる領域） | スクリプト ＋ 壁／人間 |
| **仕様が不確定** | エージェントでよい（探索・長い尾） | **最危険。エージェントに渡さない**（能力ごと剥奪 or 壁） |

- 「script-first」が正しいのは左上に限る。全面ルールにすると左下（探索）で破綻する。
- 「token コストだから script」は弱い論拠。本当の理由は **非決定論コスト**（毎回ブレる＝検証・信頼の摩耗が複利で効く）。

### なぜ皆 script を先に考えないか（機序の分解）

1. **仕様確定の強制力が無い**：script は問題を先に列挙させられる（compile / 型 / 分岐が forcing function）。prompt にはその関門が無い。
2. **媒体の錯覚**：prompt は「会話」（許容的）、code は「建築」（厳密）に感じる。媒体が要求される厳密さを隠す。
3. **長い尾が authoring 時に見えない**：agent はハッピーパスで美しくデモできる。失敗は分散の裾で、即興で埋めて静かに間違える。
4. **可逆性の錯覚**：チャットでの「再プロンプトすればやり直せる」感覚を、副作用持ち文脈に持ち込むと致命的。

## 3. エージェントに積むもの ＝ 目的 ＋ Don't（＝自由の幅）

- 法律の比喩：線を引くから内側が自由になる。線がぼやけると萎縮か暴走の両極。
- Don't は **2階建て**：
  - 広い原則（数個）＝「取り返しのつかないことは勝手にやるな」級 → **未知の事態を拾う網**
  - 具体的禁止＝「本番を消すな」「main へ直 push するな」級 → 既知の危険を名指し
- **「選択と集中」は Don't 自体にも効く**。膨らませると、せっかくの自由が死ぬ。効く Don't は少数。

## 4. なぜ「哲学軸」だけでは足りないか

- 哲学軸は判断の **確率を上げる**。でも取り返しのつかない **最悪値は縛れない**。
- 3人の Council でも同じ（AIはAI、同じ土台＝同じ盲点を共有）。3人の全会一致でも「正しい」保証にならない。
- だから **「哲学 ∧ 壁」の両方**。哲学で平均を上げ、壁で裾（最悪）を切る。
- 補助原則：従業員アナロジーは「哲学 ＋ 実績で漸増する権限」を支持する。哲学が権限制限を代替する読みは人間組織でも成立していない。

## 5. Council の位置と限界

- 役割：**曖昧な真ん中の判断を助ける推論係** ＋「迷ったら止まる → 人間へ献上」。
- 限界：**自分が迷っている時しか鳴らない**。「自信満々で間違っている時」は素通り —— そして事故はたいてい後者。
- だから **Council を取り返しのつかない操作の最後の砦にしない**。

## 6. 壁の作り方（本対話で最も詰まった所）

- **見るのは「言葉」ではなく「操作」**。AIが実際に叩くコマンド／ツール呼び出しを監査する。言葉は無限に言い換えられて漏れ、かつ誤爆する（＝禁止リストの列挙問題が単語版で再発）。操作は有限で構造化されている。
- **禁止リストではなく「原則禁止（許可制）」**。安全な操作だけ通し、取り返しのつかない操作はデフォルトで全部止める → **未知・想定外の操作が自動で安全側に落ちる**。
- **壁は Council の外に独立して置く**。Council が鳴らなくても、全会一致で GO を出しても、壁は効く。
- 「Word 一致」は **警報（鳴らすだけ・止めない）** には使ってよい。**壁には使わない**（警報と壁を混同しない）。

## 全体像

```
        ┌──────────────────────────────────┐
 壁 →   │   自由地帯（目的の内側）                │  ← 壁＝操作を監査・原則禁止で外周を囲う
（操作を  │     ├ エージェント：目的に沿って自律        │     （Council の判断では開かない）
 監査）  │     └ Council：曖昧な真ん中の判断を助ける    │
        └──────────────────────────────────┘
              ↑ 迷ったら止まる → 人間へ献上
```

| 層 | 何を見る | 動作 | 担当 |
|---|---|---|---|
| 哲学軸 | 入力・文脈 | 推論して判断 | エージェント |
| Council | 曖昧・抵触 | 合議で方針／決まらねば停止 | 3ペルソナ（推論） |
| 早期警報 | AIの出力（言葉） | 鳴らすだけ（warn） | スクリプト |
| **本物の壁** | AIが叩く**操作** | **原則禁止で止める** | スクリプト／CI |

## 既存リポジトリ機構との接続メモ（CC 側で観測）

本対話の枠組みは、本リポジトリ既存機構の以下に対応する：

- **Council**（`.claude/skills/crosscut-council/`） = §5 の「曖昧な真ん中の推論係」。第6条「人間 ≒ Council 原則」の実装主体。
- **auto-merge-boundary.md**（`.claude/skills/crosscut-autonomous-drive/references/auto-merge-boundary.md`） = §6 の「壁」候補位置。ただし現行は「不可逆かどうかの判定」を AI 自身が行う設計のため、§6 で論じた「壁を Council の外に独立して置く」「言葉ではなく操作を見る」「原則禁止（許可制）」の3点と緊張する。
- **hooks.json**（`.claude/hooks.json`） = exit code 2 (block) を第6条との緊張で明示棄却し warn のみを採用。§6 の「本物の壁」をこの hook 上には実装できない（観測専用）。**壁を hook の外（permissions / CI / 別プロセス）に置く必要**を示唆。
- **CTL（Council Trust Level）**（`philosophy.md:236-241`） = §4 補助原則の「実績で漸増する権限」に対応する既存実装。

これらの接続は本対話の射程外（採用判断は L0 へ）。

## 対話の流れ（タイムライン）

1. **出発点**：記事の「自動化スクリプト」は実はエージェント処理（context 混合）であるという確認。完全分離はしない／推論と決定論の二層／動的分水嶺、を合意済み前提として設定。
2. **why script-first？**：CC が「token コスト」論を弱論拠として斥け、非決定論コスト ＋ 4機序（仕様確定の強制力なし／媒体の錯覚／長い尾不可視／可逆性の錯覚）を提示。軸は agent/script ではなく **可逆性 × 仕様確定** であると再フレーム。
3. **哲学軸**：ユーザーが「エージェントに判断する哲学軸を与えていないのが問題」と提起。CC が同意しつつ「確率を上げるが最悪値を縛らない」「agent にとっての哲学はただの context（飾り化リスク）」「purpose without invariants ＝ confident-error generator」の3点を反論として補強。
4. **法律の比喩で合流**：ユーザーが「推論と決定論の組み合わせ（法律的ゲート）」「目的 + Don't で自由の幅」に到達。CC は Don't の2階建て化・soft/hard 振り分け・「選択と集中は Don't にも効く」で補正。
5. **Council 紹介**：ユーザーが既存実装（Council = 3ペルソナ合議）を提示。CC が「自分が迷ってる時しか鳴らない」「3ペルソナでも同じ盲点」を指摘し、壁を Council の外に独立で置くべきと提案。
6. **壁の場所**：ユーザーが「スクリプト一択、Word 一致／検出機構」を提案。CC が「言葉ではなく操作を見る」「禁止リストではなく原則禁止（許可制）」に裏返し、Word 一致は警報層に留める分け方を提示。
7. **整理 → 本ファイル**。
